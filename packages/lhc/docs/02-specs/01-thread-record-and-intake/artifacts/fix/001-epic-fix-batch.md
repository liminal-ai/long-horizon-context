# Epic Fix Batch 1 — from canonical epic review (artifacts/epic/001-epic-review.json)

Bounded fixes for the current epic-review findings. Each item is in scope for this pass.

- **F-EPIC-001 (blocker)**: `threads.newThread` accepts an empty/blank `filePath` and registers a thread with no durable file. `src/domains/threads/index.ts:73` guards only with `existsSync(filePath)`; `node:sqlite` `DatabaseSync('')` opens a temporary database that vanishes on close, so the operation returns ok and inserts a registry row for `filePath: ""`. Fix: reject empty or whitespace-only `filePath` (and any path that cannot produce a durable file) as `caller_error` before touching storage, at the SDK surface so both SDK and CLI get the guard. Add red tests: SDK `newThread({ filePath: "" })` → caller_error with nothing created and no registry row; CLI `threads new-thread --file-path ''` → JSON error, exit 1, clean registry. Mirror the check in `resolveThreadRef` for `{ filePath: "" }` so read paths fail closed with `caller_error` rather than opening a temp database.
- **F-EPIC-002**: Read-back surfaces (`listEvents`, `listMessages`, `listTurns`, `listQueuedWork`) skip thread-reference validation present on the write path, so malformed references (e.g. empty path) reach storage open. Fix: route all read surfaces through the same `resolveThreadRef` validation used by writes; empty/invalid refs return `caller_error`/`thread_not_found` consistently at SDK and CLI layers. Add a small test per read surface for the empty-path and unknown-id legs.
- **NB-2**: CLI parses flags with `strict: false`, silently ignoring unknown or misspelled flags (e.g. `--file-pth`). Fix: enable strict flag parsing in the CLI arg parser and return the existing structured usage error (`caller_error` with the CLI-adapter code pattern) naming the unknown flag; keep exit code 1. Update/extend the CLI process suite leg for an unknown-flag case.
- **NB-5**: Dead code and stale artifacts. Remove the uncalled `notImplemented()` helper from `shared/errors.ts` (all stubs are gone since Story 5). Clean stale pre-epic compiled output from `dist/` (`dist/commands/`, `dist/thread-events/`, `dist/token-counting/`) — add a `prebuild` clean (e.g. `rm -rf dist` before `tsc`) or equivalent so `dist/` always reflects current `src/`.

Out of scope for this batch (tracked separately): NB-1 (empty-string payload text — pending human ruling on epic-vs-tech-design conflict), NB-4 (test seams are sanctioned by the test plan's architecture-risk rows; no change), work_item constraint vocabulary (Epic 02 owns lifecycle schema).
