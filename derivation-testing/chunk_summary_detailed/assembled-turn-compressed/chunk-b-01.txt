Generalizing about public interfaces, naming, and coherence:

1. Let the outer surface carry part of the meaning. If the surface is `intake`, don’t repeat intake-like verbs inside it; prefer `intake message-events` over `intake record-activity`.

2. Use specific-enough compound names. A generic word can work if paired with a clarifier: `events` alone is vague, `message-events` is more legible.

3. Name from the caller’s mental model, not storage behavior. Avoid `append` if the caller thinks “I’m sending message events.”

4. Prefer short, concrete phrases over mushy abstraction words. `activity` is broad and low-imprint; `message-events` is easier to remember.

5. Specificity is contextual. `new-thread --file-path` works because the operation says what is created and the flag says what kind of value is needed; you don’t need `--thread-db`.

6. Coherence comes from phrase composition: action frame + object, not verb + verb or implementation + object.

7. A public interface should reduce hidden questions.

8. Operation names should imprint: short, concrete terms are easier for tired humans and agents to carry.
