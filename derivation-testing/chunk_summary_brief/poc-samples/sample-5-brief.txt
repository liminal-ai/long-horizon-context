Track two improvement streams: `ls-publish-epic` for story shape/publish quality and `ls-enrich` for implementation readiness.

Publish/sharding improvements:
- Add explicit story-shape review before publishing: story type, governing idea, overload flags, split/keep decision.
- Require one clear governing idea per story; split stories with multiple centers.
- Formalize story archetypes: foundation, adapter, semantic rule, orchestration, metadata, packaging, repair/recovery.
- Flag lifecycle mixing: onboarding/import/migration/recovery vs steady-state.
- Flag repair/recovery bundled into happy path when invariants differ.
- Review authority boundaries: source truth vs derived state; whether ownership/authority changes.
- Preserve explicit future-feature boundaries.
- Expand integration trace beyond user flow to runtime entrypoint, persistence/reopen, source→derived, generated output, operator command.
- Clarify TC ownership is single-story, though later integration/E2E coverage may span stories.

Enrichment improvements:
- Make Build Strategy a standard section.
- Require story-specific risk reminders, not generic gate reminders.
- Add Production Path Proof for runtime/adapter/CLI/API stories: entrypoint, registration, default deps, runtime/E2E evidence.
- Add boundary-reconciliation prompts: service vs production path, fixture vs real runtime, in-memory vs persisted, workspace vs committed, source truth vs projection.
- Systematically derive non-TC architecture/risk tests.
- Strengthen anti-shim guidance: no helper-only runtime proof, fake registration, silent skipped integration, in-memory-only persistence proof, placeholder generated artifact.
- Add Runtime Contract Assumptions.
- Require fixture realism notes where fixtures/persistence/runtime matter.
- Reference coverage/test ownership artifacts where relevant.
- Distinguish targeted verification, story gate, epic gate, optional runtime/E2E.

Cross-cutting issues:
- Acceptance must require committed production entrypoints/artifacts, not only workspace state.
- Integration gating should detect zero integration-test runs.
- Final artifact/gate labeling can drift from logs.
- Quick-fix vs story-continue routing should respect Build Strategy, especially high-risk stories.

Core takeaway: make expert judgment explicit: why this is one story, what makes it risky, and whether verified workspace state became committed runtime truth.
