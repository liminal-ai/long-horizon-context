Chunk 1 of Phase 3 of the LHC project. Your job is to find what is wrong
with it. A clean report is a real possible outcome, but assume nothing is
correct until you have checked it against the source yourself.

You are **read-only**: do not fix anything, do not commit, do not edit
files. Report findings.

## What to check — be specific, cite `file:line`

1. **Scope containment.** Every changed file. Core touches must be exactly
   the three enumerated in the brief (`xai-grok-shell/Cargo.toml`,
   `session/acp_session_impl/spawn.rs`, `agent/handlers/model_switch.rs`)
   plus the root `Cargo.toml` members entry. Anything else, or any edit
   inside the vendored submodule, is a critical finding.
2. **Hook discipline.** Each hook 1–5 additive lines, marked
   `// LHC-HOOK <n>/3:`, no host logic displaced into LHC.
   `scripts/check-lhc-hooks.sh` has `EXPECTED_HOOKS=3` and a named
   assertion for the root Cargo.toml members entry; FORK.md's touchpoint
   inventory table matches reality exactly. **Run the script yourself** and
   report its actual output.
3. **Off-by-default.** With `GROK_LHC` unset: is the host path genuinely
   unchanged? Look for anything constructed, spawned, opened, or written
   before the gate is consulted. A file created or a task spawned in the
   off path is a serious finding.
4. **The mapping — the core of this chunk.** Compare the adapter's
   `ConversationItem` → `MessageEventInput` mapping against BOTH sides:
   - host: `crates/codegen/xai-grok-sampling-types/src/conversation.rs`
     (`ConversationItem` variants, `SyntheticReason`'s 18 variants,
     `UserItem` fields);
   - LHC: `crates/lhc/vendor/.../packages/lhc-rs/src/intake_stream/mod.rs`
     (`EVENT_KINDS` (9), payload structs — all `deny_unknown_fields`).
   Look hard for: **any wildcard `_ =>` arm over a host enum** (banned —
   upstream vocabulary drift must be a compile error); silently dropped
   variants; `Reasoning` items misrouted; `BackendToolCall` dropped;
   `is_error` lost; synthetic user items misclassified as real user
   prompts (or vice versa); payload fields that will fail LHC's
   `deny_unknown_fields` decode at runtime; a mapping table that claims
   coverage the code does not have.
5. **Idempotency keys.** Are they genuinely stable across process restart,
   replay, resume, rewind, retry, and session fork? Any dependence on wall
   clock, RNG, hash-map iteration order, pointer/address, or a counter that
   resets on restart is a finding. Trace one key derivation by hand and say
   what it is composed of. Do the tests actually prove re-replay yields
   zero new events, or do they assert something weaker?
6. **Assertion fidelity.** This implementor's known failure mode is
   weakened assertions and tests that pass without proving the claim. For
   every certification item in the brief (restart, replay, fork, rewind,
   idempotency, concurrency, injected crash, disabled-path), find the test
   and judge whether it proves the claim or merely exercises the code.
   Goldens under `crates/lhc/grok-lhc-host/tests/goldens/` must cover every
   emitted event kind — check coverage against the mapping table, and check
   that goldens were not generated by the very code they certify without
   any independent anchor.
7. **Host-obligation compliance.** `SdkConfig.clock` must NOT be set in
   production. Timestamps passed into LHC APIs must be canonical
   `YYYY-MM-DDTHH:MM:SS(.mmm)Z` (no offset forms). Both are recorded
   obligations from the Phase 2 acceptance record.
8. **Failure isolation and resource hygiene.** LHC failure must not break
   the host session. Check for `unwrap`/`expect`/panic paths reachable from
   host callbacks, blocking calls on an async actor thread (the
   `ChatPersistence` methods run inside the chat-state actor — a blocking
   SQLite write or a `block_on` there stalls the whole session; this is a
   serious finding if present), unbounded channel growth, and background
   tasks that outlive teardown.
9. **Build and lint.** Run yourself and report actual output:
   `cargo check --manifest-path crates/lhc/grok-lhc-host/Cargo.toml`,
   `cargo test --manifest-path crates/lhc/grok-lhc-host/Cargo.toml`,
   `cargo check -p xai-grok-shell`, `cargo fmt --check` and `cargo clippy`
   on touched files. (`. "$HOME/.cargo/env"` first if cargo is missing.)
10. **Ledger honesty.** Does FORK.md / the implementor's report claim
    anything the tree does not support?

## Report format

Findings only — no summary of what the code does. For each finding:
`file:line`, severity (critical / major / minor), what is wrong, the
evidence (cite the host or LHC source you compared against), and the
minimal correct fix.

End with an explicit **coverage note**: which files you reviewed line by
line, which you only skimmed, and which you did not open. Be honest — an
inflated coverage claim is worse than a narrow one.

Do not consult or wait for any other verifier. Deliver your own verdict:
**PASS** (nothing blocking) or **CHANGES REQUIRED**.
