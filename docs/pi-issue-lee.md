# Thinking blocks inappropriately stripped in newer Claude models

## What happened?

On Anthropic models where `thinking.display` defaults to `"omitted"` (claude-fable-5, claude-sonnet-5, claude-opus-4-7+), thinking blocks come back with empty `thinking` text and the actual reasoning carried in the `signature` field. pi stores these fine. But when building the next request, `convertMessages` (packages/ai/src/api/anthropic-messages.ts) skips any thinking block with empty text before it ever checks the signature:

```ts
if (block.thinking.trim().length === 0) continue;
```

So on these models the model never gets its prior thinking back. Any turn, including mid tool-use loop. Nothing errors, the reasoning is just silently gone. Anthropic's docs say signed blocks need to be echoed back, and these models keep prior thinking in context by default.

Docs: https://platform.claude.com/docs/en/build-with-claude/adaptive-thinking, https://platform.claude.com/docs/en/build-with-claude/extended-thinking

## Steps to reproduce

Direct against api.anthropic.com with a plain API key, no extensions (repro is at the pi-ai stream level). Sonnet 5 shows it.

1. Turn 1: prompt that triggers thinking + a tool call. Assembled assistant message has `thinking: ""` and a ~400 char `thinkingSignature`.
2. Turn 2: send assistant message + toolResult back, capture the outgoing request body:

```
0 user      [text]
1 assistant [text, tool_use]     <- thinking block dropped, signature discarded
2 user      [tool_result]
```

## Expected behavior

The thinking block echoed back with its signature. From the extended-thinking docs: "the entire sequence of consecutive thinking blocks must match the outputs generated by the model during the original request."

Looks like the empty-text skip predates display-omitted and was right at the time (fits the #3936 aborted-stream case, content without signature). This is the inverse shape, signature without content, and on current models it's the normal case rather than a corruption. `redacted_thinking` is already passed back correctly btw.

Running a local patch in the meantime: https://github.com/leegmoore/pi/commit/1a44f939e653a35479a4b6cda63f174856615ded

## Version

pi-ai 0.80.x (main @ ee24a9ec)
